# pptx-slim

**把 `.pptx` 压到指定大小以内 —— 版式、文字、动画一帧都不动。**

投稿系统、基金申报、教务上传，到处都有 5 MB / 10 MB / 20 MB 的上限。一个塞满手机照片的 PPT 轻轻松松就超标。市面上大多数「PPT 压缩」要么无脑重压一遍，出来糊成一片；要么把你的动图悄悄压成一帧静止画面。

`pptx-slim` 两样都不做。它先算出每张图**在版面上实际占几英寸**，反推它真正需要多少像素，再按这个把字节预算分下去。

> 一张 4032×3024 的手机照片，在幻灯片上只占 4.5 英寸宽。按 200 DPI 算，它只需要 900×675 —— 大约 3% 的像素。你那 20 MB 就是这么来的。

## 安装

```bash
pip install git+https://github.com/Forever61T/pptx-slim.git
```

或者直接把 `pptx_slim.py` 下载下来用。唯一的依赖是 Pillow：

```bash
python3 -m pip install --user Pillow
```

## 用法

```bash
pptx-slim 汇报.pptx            # 压到 5 MB 以内（默认）
pptx-slim 汇报.pptx 20         # 压到 20 MB 以内
pptx-slim 汇报.pptx 5 --inplace        # 覆盖原文件
pptx-slim 汇报.pptx 5 --out 小.pptx    # 指定输出路径
pptx-slim 汇报.pptx 5 --lang en        # 强制英文输出
```

不加 `--out` 也不加 `--inplace` 时，结果会放在原文件旁边，命名为 `汇报 (compressed).pptx`。**原文件永远不动。**

## 它拒绝碰的东西，以及为什么

这才是关键。压了这些，文件确实更小了 —— 但也**坏了**：

| 必须保留 | 原因 |
|---|---|
| **动图 GIF** | 用 Pillow 重编码**反而更大**（实测 162% 和 167%），而真要压小就得丢帧。你的动画原样保留。 |
| **带真透明的图** | 转成 JPEG 会把每个透明像素变成白块 —— 彩色背景上的校徽、logo 会顶出一个白方框。注意只认**真**透明：一层全不透明的 alpha 通道会按不透明处理，照压不误。 |
| **小于 50 KB 的图** | 压不出多少，风险却是实打实的。 |

如果排除这些之后还是压不到目标，工具会**如实告诉你**，并把能做出的最小版本交给你，而不是偷偷去动它不该动的东西。

## 安全网

把 `image4.png` 改名成 `image4.jpg`，会让所有指向它的关系文件失效；而一个 `[Content_Types].xml` 没声明过的部件扩展名，会让 PowerPoint 弹出「发现内容有问题，是否修复？」。多数快脚本都栽在这里。

每一份产物在交给你之前都会过一遍检查：

- 所有 XML 部件格式合法
- 每一条内部关系都能找到对应部件
- 每个部件的扩展名都在 `[Content_Types].xml` 里声明过 —— 源文件只声明了 `jpg` 时，工具就用 `jpg`，绝不硬造一个 `jpeg`
- 改名后的素材，会在所有 `.rels` 和幻灯片引用里同步改掉

任何一项不过，程序**直接中止，而不是交给你一个坏文件**。

## 支持哪些系统

引擎是纯 Python —— 只用标准库加 Pillow，没有任何 macOS 专有调用。
凡是装得上 Python 3.8+ 和 Pillow 的地方都能跑：macOS、Windows、Linux 都可以。

「拖拽外壳」则是分平台的，因为「把文件拖到图标上」这件事本身就不可移植：

| 系统 | 外壳 | 说明 |
|---|---|---|
| macOS | `macos/build.sh` | 生成内嵌引擎的 `.app` 拖拽程序 |
| Windows | `windows/run.bat` | 把 `.pptx` 拖到 `.bat` 上，或双击后粘贴路径 |
| Linux | — | 直接用命令行：`python3 pptx_slim.py 汇报.pptx 5` |

### macOS

```bash
macos/build.sh                    # 生成「PPT Slimmer.app」
APP_NAME="PPT瘦身" macos/build.sh  # 或者换个中文名
```

把 `.pptx` 拖到图标上，输入目标 MB，它会把结果报给你。引擎内嵌在 app 包里，独立可用。
它只做了 ad-hoc 签名，所以**第一次打开**要先按住 Control 点图标 →「打开」
（或者在终端里跑 `xattr -cr /Applications/PPT瘦身.app`）。

### Windows

把 `.pptx` 拖到 `windows\run.bat` 上即可。它会自动找你机器上的 Python
（`python` 或 `py` 启动器），缺 Pillow 会帮你装上，然后问你要压到多少 MB。
需要先从 [python.org](https://www.python.org/downloads/) 装 Python，
安装时记得勾选 **Add python.exe to PATH**。

### 打包发布

`ditto -c -k` 会把中文文件名按 UTF-8 字节写进去，却**不设 UTF-8 标志位**，
于是 `PPT瘦身.app` 到了 7-Zip、WinRAR 和 Windows 资源管理器里就变成
`PPTτÿªΦ║½.app`。请改用仓库自带的打包器 —— 它会设好标志位，
同时照样保住符号链接和权限位：

```bash
python3 tools/zip_app.py "PPT瘦身.app" 发布包.zip
```

（macOS 自带的 `/usr/bin/unzip` 是 Info-ZIP 6.00，两种情况下都显示乱码 ——
那是这个上古工具的毛病，不是压缩包的问题。）

## 参数

| 参数 | 含义 |
|---|---|
| `target_mb` | 目标大小（MB），默认 `5` |
| `--out PATH` | 输出到指定路径 |
| `--inplace` | 覆盖原文件 |
| `--lang en\|zh` | 强制输出语言（否则读 `LANG`/`LC_ALL`） |
| `--quiet` | 不打印报告 |
| `--version` | 显示版本 |

## 原理

1. **量。** 解析每一张幻灯片、版式、母版和备注页。对每张图读出 `a:ext` 变换（EMU，每英寸 914400），得到它**被画出来**的尺寸 —— 不是它的像素尺寸。
2. **分预算。** 扣掉所有必须留下的（非图片部件、动图、透明素材），剩下的字节预算按**版面面积**分给可压缩的图。整页大图分到的字节，自然比一英寸的小图标多。
3. **压。** 每张图先缩放到当前 DPI 档位下它真正需要的像素，再把 JPEG 质量往下二分，直到塞进它那一份。
4. **加码。** 整份还是超标，就降 DPI 重来一轮 —— **高画质的低分辨率，胜过低画质的高分辨率**。
5. **体检、打包。** 改写关系引用，复查包结构，重建 zip（`[Content_Types].xml` 排在最前）。

## 已知限制

- **只支持 `.pptx`。** 旧版二进制 `.ppt` 不支持。
- **内嵌视频和音频不动。** 现代 PPT 里体积大头往往是它们；重编码视频是另一个问题、另一套取舍，悄悄劣化别人的录像，比超标更糟。
- **字体不做子集化。** 内嵌字体整份保留。
- **只处理位图。** EMF/WMF 矢量图不做转换（转了通常更糟）。
- 需要 Python 3.7+ 和 Pillow。
